# Mastering Spec-Driven Development (SDD)

> [English version](INDEX.md) · [Оглавление курса](INDEX.ru.md)

> *«Если ИИ не смог построить это правильно, виновата спецификация, а не код.»*

Полный курс, который учит разработчиков перестать писать код через расплывчатые промпты и начать **проектировать системы через структурированные спецификации**. К концу вы будете думать как продуктовый архитектор — писать спецификации, которые любая модель ИИ сможет исполнить точно.

## Зачем существует этот курс

Ландшафт ИИ-кодинга прошёл три различных эпохи:

1. **Vibe Coding (2022–2024)** — «Сделай мне страницу входа» и надежда на лучшее
2. **Structured Prompting (2024–2025)** — промпты лучше, но всё ещё слишком неоднозначны для сложных систем
3. **Spec-Driven Development (2025 — настоящее время)** — формальные спецификации как контракты между замыслом человека и исполнением ИИ

Большинство разработчиков всё ещё застряли в эпохах 1 или 2. Этот курс ведёт вас в эпоху 3.

## Чему вы научитесь

- Писать **микро-спецификации** с контекстом, целью и ограничениями, устраняющие неоднозначность
- Проектировать **схемы, контракты компонентов и чертежи API** до написания кода
- Строить **конвейеры валидации**, где тесты генерируются из спецификаций до реализации
- Оркестрировать **мультиагентные рабочие процессы** (архитектор, строитель, критик) для сложных задач
- Управлять **эволюцией спецификаций** при изменении требований, не ломая существующие системы
- Освоить **human-in-the-loop** — точно знать, где ИИ отклоняется, и как это предотвратить

## Что внутри каждой главы

Каждая глава написана как **полная лекция** терпеливого и знающего профессора и включает:

- Реальные примеры, основанные на том, как **Anthropic, Google, OpenAI, Meta, Microsoft, Stripe** и другие лидеры отрасли подходят к этим проблемам
- Код примеров продакшн-уровня на **TypeScript, Python, YAML и JSON** (не псевдокод)
- Вставки **«Заметка профессора»** с выстраданной мудростью и отраслевым контекстом
- **Практические упражнения** с критериями оценки
- **Антишаблоны** — чего НЕ делать и почему

## Ключевые понятия кратко

| Понятие | Что означает |
|---------|---------------|
| **Микро-спецификация** | Структурированная спецификация с тремя столпами: контекст, цель, ограничения |
| **SSOT** | Единый источник истины — спецификация авторитетна; код выводится из неё |
| **Intent Drift** | Когда вывод ИИ постепенно отклоняется от исходной спецификации |
| **Approval Gate** | Человеческая контрольная точка, где работа ИИ проверяется перед продолжением |
| **Spec Coverage** | Какая доля спецификации имеет соответствующие тестовые случаи |
| **Architect/Builder/Critic** | Трёхагентный шаблон для ИИ-разработки в масштабе |
