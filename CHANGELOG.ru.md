# Журнал изменений

Все значимые изменения Specter документируются в этом файле.

## [0.3.1] - 2026-04-04

### Исправлено

- ID по пути маршрута теперь имеет приоритет над логикой общих имён файлов для Next.js App Router (`onboarding-route` → `onboarding`)
- Zod `.min(N, "message")` / `.max(N, "message")` / `.email("msg")` с пользовательскими сообщениями об ошибках теперь извлекаются корректно
- CLI находит `prisma/schema.prisma` в родительских каталогах при сканировании подкаталога
- Устранены ложные срабатывания на встроенные комментарии Python (`# isort:skip`, `# noqa` в строках импорта)

### Добавлено

- Флаг `--overwrite` для `specter reverse` — существующие файлы спецификаций по умолчанию пропускаются, что сохраняет ручные правки
- Флаг `--exclude` для `specter reverse` — ограничение области сканирования исключениями путей
- Трёхуровневый CI-процесс предварительного выпуска, проверяющий 12 open-source репозиториев (chi, fiber, validator, FastAPI, pydantic, django, cal.com, create-t3-app, payload, tRPC, TanStack, refine)

## [0.3.0] - 2026-04-03

### Добавлено

- Манифест проекта `specter.yaml` — определяет метаданные системы, группировку по доменам, пороги покрытия и реестр спецификаций
- Команда `specter init` — создаёт specter.yaml из существующих спецификаций с флагами `--name` и `--force`
- Группировка по доменам — объединение спецификаций по бизнес-области (платежи, аутентификация, контент) с наследованием уровней
- Каскад уровней — уровень спецификации → уровень домена → уровень системы → значение по умолчанию (2)
- Настраиваемые пороги покрытия для каждого уровня через `settings.coverage` манифеста
- Автоматически поддерживаемый реестр спецификаций, перестраиваемый при каждом запуске sync
- Агрегация покрытия на уровне домена
- `spec-manifest.spec.yaml` — собственная спецификация манифеста (10 ограничений, 14 AC)
- 104 теста (было 85), 7 спецификаций (было 6)

## [0.2.4] - 2026-04-03

### Исправлено

- ID по пути маршрута теперь имеет приоритет над логикой общих имён файлов для файлов Next.js App Router (`onboarding-route` → `onboarding`, `slug-route` → `blog-slug`)
- Zod `.min(N, "message")` и `.max(N, "message")` с пользовательскими сообщениями об ошибках теперь извлекаются корректно (ранее регулярное выражение для закрывающей скобки не срабатывало при наличии дополнительных аргументов)
- Zod `.email("message")` и `.url("message")` с пользовательскими сообщениями теперь извлекаются корректно
- CLI находит `prisma/schema.prisma` в родительских каталогах при сканировании подкаталога вроде `src/`

### Добавлено

- Флаг `--exclude` для `specter reverse` — исключение путей из сканирования (например, `--exclude src/components --exclude "*.test.*"`)

## [0.2.3] - 2026-04-03

### Исправлено

- Встроенные комментарии Python удаляются перед извлечением ограничений — устранены ложные срабатывания из `# isort:skip`, `# noqa` и т.п. в строках импорта (Django: 67 → 31 ограничение, удалено 36 ложных срабатываний)

## [0.2.2] - 2026-04-03

### Исправлено

- P0: неизвестные значения `validation.rule` отображаются в `"custom"` — Specter больше не отвергает собственный вывод для тегов структур Go (`gte`, `lte`, `oneof`), kwargs полей Python (`min_length`, `max_length`) или атрибутов Prisma (`unique`)
- P1: добавлены `.spec.tsx`, `.spec.jsx`, `.spec.js` в обнаружение тестовых файлов TypeScript — ранее 713 тестовых утверждений молча терялись в refine
- P1: исправлено обрезание описания теста на встроенных кавычках — `it("'visible' value")` больше не обрывается на первом `'`
- P1: директивы-комментарии Python (`# isort`, `# noqa`, `# type:`, `# pragma`) отфильтровываются при извлечении ограничений
- P2: родительский каталог учитывается в ID спецификации для общих имён файлов (`index.ts` → `auth-index`, `main.go` → `rest-main`, `route.ts` → `users-route`)

### Добавлено

- `normalizeValidationRule()` в ядре с таблицей псевдонимов (gte→min, lte→max, oneof→enum и т.д.)
- Список обнаружения общих имён файлов для предотвращения коллизий ID спецификаций
- Документ плана улучшений (`docs/IMPROVEMENT_ROADMAP.md`)
- Обновлён CLAUDE.md: формулировка миссии, принцип проектирования и система приоритетов ошибок

## [0.2.1] - 2026-04-03

### Исправлено

- Исправлено падение при null `validation.value`, когда в шаблонах Zod нет извлекаемого литерала (`.email()`, `.url()`, `.optional()`, `.refine()`, `z.boolean()`, `z.array()`)
- Исправлено: все файлы Next.js App Router генерировали одинаковый ID спецификации `route` — теперь ID выводится из пути маршрута (например, `/api/webhooks/stripe` → `webhooks-stripe`)
- Путь исходного файла включается в диагностику `validation_failed` для упрощения отладки
- `package.json`/`go.mod`/`pyproject.toml` ищутся в родительских каталогах для вывода имени системы

### Добавлено

- Адаптер TypeScript: извлечение ограничений из перечислений TypeScript, объединённых типов и массивов `as const`
- Адаптер TypeScript: извлечение ограничений из файлов схем Prisma (`.prisma`) — типы полей, `@unique`, `@db.VarChar(N)`, обязательность/необязательность
- Адаптер TypeScript: извлечение ограничений ролей и статусов из шаблонов кода (например, `session.user.role === "ADMIN"`)
- Адаптер TypeScript: распознавание шаблонов Zod `.url()`, `z.boolean()`, `z.array()`
- Перечисление Zod теперь извлекает значения (например, `z.enum(["a", "b"])` → `Value: "a", "b"`)
- 85 тестов (было 77)

## [0.2.0] - 2026-04-03

### Добавлено

- Команда `specter reverse` — обратный компилятор извлекает черновик .spec.yaml из существующего кода
- Архитектура плагинов-адаптеров с 3 встроенными адаптерами: TypeScript, Python, Go
- Адаптер TypeScript: схемы Zod, тесты Jest/Vitest, маршруты Next.js/Express
- Адаптер Python: модели Pydantic, тесты pytest, маршруты FastAPI/Django
- Адаптер Go: теги валидации структур, табличные тесты, маршруты net/http/gin/chi
- Обнаружение пробелов: помечает ограничения без тестового покрытия
- Автоопределение языкового адаптера по расширению файла
- spec-reverse.spec.yaml (10 ограничений, 14 AC)
- Всего 77 тестов (было 37)

## [0.1.0-alpha.2] - 2026-04-02

### Изменено

- Кроссплатформенная поставка бинарников через goreleaser (linux, darwin, windows)
- Пакет DEB доступен для Debian/Ubuntu

### Добавлено

- Рабочий процесс выпуска GitHub Actions (по тегу)
- Файлы сообщества: шаблоны issue, шаблон PR, CODEOWNERS
- CHANGELOG.md

## [0.1.0-alpha.1] - 2026-03-28

### Добавлено

- Первая реализация Specter на TypeScript
- Инструменты MVP: parse, resolve, check, coverage, sync
- Каноническая схема спецификаций (JSON Schema draft 2020-12)
