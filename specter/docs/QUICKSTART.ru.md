# Specter QuickStart

От нуля до работающего конвейера спецификаций менее чем за 5 минут.

---

## 1. Установка

**Самый быстрый путь — расширение VS Code:** найдите `Specter SDD` в панели Extensions, установите, затем один раз выполните **Specter: Add CLI to Shell PATH** из командной палитры. Расширение использует CLI, уже находящийся в PATH, если его версия поддерживается, иначе скачивает собственную копию; команда shell PATH кладёт копию в `~/.specter/bin/specter` для вашего терминала.

**Только CLI, macOS / Linux:**
```bash
OS=$(uname -s | tr '[:upper:]' '[:lower:]')
ARCH=$(uname -m); case "$ARCH" in x86_64) ARCH=amd64 ;; aarch64) ARCH=arm64 ;; esac
VERSION=$(curl -sL https://api.github.com/repos/Hanalyx/specter/releases/latest | grep '"tag_name"' | head -n1 | cut -d'"' -f4 | sed 's/^v//')
curl -LO "https://github.com/Hanalyx/specter/releases/download/v${VERSION}/specter_${VERSION}_${OS}_${ARCH}.tar.gz"
tar xzf "specter_${VERSION}_${OS}_${ARCH}.tar.gz" && sudo mv specter /usr/local/bin/
specter --version
```

**Только CLI, Windows (PowerShell):**
```powershell
$v = (Invoke-RestMethod https://api.github.com/repos/Hanalyx/specter/releases/latest).tag_name -replace '^v',''
Invoke-WebRequest -Uri "https://github.com/Hanalyx/specter/releases/download/v${v}/specter_${v}_windows_amd64.zip" -OutFile specter.zip
Expand-Archive specter.zip -DestinationPath "$env:USERPROFILE\.specter\bin"
[Environment]::SetEnvironmentVariable("Path", "$env:Path;$env:USERPROFILE\.specter\bin", "User")
```

О `.deb`, `.rpm` и других способах установки см. [README Specter](../README.ru.md#install).

## 2. Загрузите спецификации из своего кода

Направьте Specter на каталог с исходниками, и он автоматически сгенерирует черновики спецификаций:

```bash
specter reverse src/        # TypeScript / JavaScript
specter reverse app/        # Python / Django / FastAPI
specter reverse ./          # Go
```

Будет создан каталог `specs/` с одним `.spec.yaml` на группу файлов.

> **Уже есть спецификации?** Specter использует собственную схему (см. [Справочник по схеме](SPEC_SCHEMA_REFERENCE.ru.md)).
> Выполните `specter reverse --dry-run --json src/`, чтобы предпросмотреть результат,
> затем решите, мигрировать существующие спецификации или начать заново.

---

## 3. Инициализируйте рабочее пространство

```bash
specter init
```

Создаёт `specter.yaml` — манифест, сообщающий Specter (и расширению VS Code), где лежат ваши спецификации и тесты.

---

## 4. Просмотрите одну спецификацию

Откройте любую сгенерированную спецификацию в VS Code. Она будет выглядеть так:

```yaml
spec:
  id: user-create
  version: "1.0.0"
  status: draft
  tier: 2
  context:
    system: User service
  objective:
    summary: "Create a new user account"
  constraints:
    - id: C-01
      description: "POST /users accepts email and password"
  acceptance_criteria:
    - id: AC-01
      description: ""        # ← empty, needs your intent
      gap: true              # ← human review needed
```

Флаг `gap: true` стоит на отдельных критериях приёмки, которые обратный компилятор извлёк структурно, но не смог вывести их замысел. Пока эти пробелы не закрыты, AC считается непокрытым (`specter sync` на нём упадёт), что и заставляет провести триаж.

**Передайте этот промпт своему ИИ-ассистенту:**

```
Here is a draft spec generated by Specter's reverse compiler:

[paste the spec]

Please:
1. Fill in all empty acceptance_criteria descriptions with clear, testable behavior
2. Add any constraints that are obviously missing based on the context
3. Remove the `gap: true` flag once all gaps are filled
4. Keep all existing IDs (C-01, AC-01, etc.) unchanged
5. Use MUST/MUST NOT language for constraints per RFC 2119
```

## 5. Аннотируйте один тест

Добавьте две строки комментариев к существующему тесту:

```typescript
// @spec user-create
// @ac AC-01
test('creates user and returns 201', async () => { ... });
```

```python
# @spec user-create
# @ac AC-01
def test_create_user_returns_201(): ...
```

```go
// @spec user-create
// @ac AC-01
func TestCreateUser_Returns201(t *testing.T) { ... }
```

Комментариев к исходнику достаточно для `specter coverage`. Для `specter coverage --strict` также покажите `user-create/AC-01` в заголовке теста или напечатайте `@spec` и `@ac` во время теста перед запуском `specter ingest`.

---

## 6. Проверьте покрытие

```bash
specter coverage
```

```
Spec ID        Tier  ACs  Covered  Coverage  Status
user-create    T2    3    1        33%       FAIL   ← below T2's 80% threshold
  uncovered: AC-02, AC-03
```

Спецификации tier 2 нужно 80% покрытия для прохождения; tier 1 — 100%; tier 3 — 50%. Каждая добавленная аннотация `@ac` повышает процент. Как только `user-create` достигает 80%+, статус меняется на `PASS`, и `specter sync` может пройти.

---

## 7. Запустите весь конвейер

```bash
specter sync
```

```
PASS parse:    1 spec parsed
PASS resolve:  no dependency issues
PASS check:    0 errors
PASS coverage: thresholds met

All checks passed.
```

Добавьте это в CI, и вы защищены.
